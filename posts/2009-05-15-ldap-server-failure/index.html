LDAP Server failure

May 15, 2009 One-minute read
Technology • Business

One of my customer sites experienced a catastrophic server failure, with the primary LDAP authentication server going down first and the rest daisy-chaining after that.A quick look at the message logs didn’t reveal anything unusual, and restores from backups didn’t help at all. I began to suspect something wrong with the program’s databases, and deleted them away, and recreated them after backing up the customer’s LDAP datastores on the secondary LDAP server.Voila. But that was after a whole day of deciphering where it went wrong.A few lessons which I’ve learnt along the way.1. It’s never good to try to restore from backup immediately, but it does pay to understand the problem and to rectify it.2. A secondary LDAP server is a must for any site. That was the saving grace and provided me the means to restore the site quickly.3. It’s not good to do a backup of the LDAP server through an export of the LDIF file. It’s a lot better to backup the entire directory server instance.Hope it won’t happen again.
