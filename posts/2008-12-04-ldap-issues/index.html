LDAP issues

December 4, 2008 One-minute read
Technology • Business

In the current project I’m leading right now, I was faced with an interesting issue - integrating a Solaris LDAP client with a Sun Enterprise Directory server running on SUSE Linux 10 SP1.Now, Solaris’ LDAP client behaves very differently from Linux’s OpenLDAP client, so much so as to warrant a whole treatment on the subject. But that’s for another day.Anyway, I took a look at the log files.findBaseDN: ldap not runningfindBaseDN: calling __ns_ldap_default_config()found 1 namingcontextsfindBaseDN: __ns_ldap_list(NULL,"(&(objectclass=nisDomainObject)(nisdomain=xxx.xxxx.nz))“rootDN[0] dc=xxxx,dc=xxxxx,dc=nzNOTFOUND:Could not find the nisDomainObject for DN dc=xxxx,dc=xxxx,dc=nzfound_cxt = -1findBaseDN: Err exitFailed to find defaultSearchBase for domain xxxx.xxxx.nzsnippet>Darn, the stupid LDAP client expects to find an NIS domain first BEFORE parsing it to reveal the LDAP domain. sighI then inserted the attributes that were required (nisDomainObject key and nisDomain attribute) into the baseDN.And presto,bash-3.00# ldapclient manual \ > -a domainName=xxxxx.xxxx.nz \ > -a defaultSearchBase=dc=xxxx,dc=xxxx,dc=nz \ > 10.x.x.xxSystem successfully configured#>What a lovely result.
